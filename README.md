# AniimoPalworldToolkit

A modular Python toolchain for porting **legally usable** creature assets from
Aniimo (reported to be a customised Unity engine) into **Palworld**
(Unreal Engine 5.1) mods, one creature at a time.

The goal is a "creature porting studio": pick an Aniimo, extract, auto-map,
convert, inspect and fix, configure regional forms, Normal/Prismana forms and the
12 Shiny appearances (independent rare rolls; Prismana Shiny is the rarest), combat
(the Aniimo Ultimate becomes the Pal's Partner Skill), validate, and export a
Palworld mod. See [docs/architecture.md](docs/architecture.md).

> **Status: milestones 1–3 done, milestone 4 (conversion) in progress.**
> - **Working:** scanning a game folder, listing the objects inside its Unity
>   files, building a creature catalog with automatic asset association,
>   saving resumable per-creature projects, and extracting assets with UnityPy
>   and AssetRipper.
> - **Tested on synthetic Unity data only** (generated by the tests and opened
>   by both UnityPy and a real AssetRipper build). **Not yet tested on real
>   Aniimo files.**
> - **Conversion:** rigged FBX with retargeted clips works on synthetic data
>   (verified with Blender 5.2 as a Python module). Materials in the FBX and
>   Palworld-skeleton retargeting are next.
> - **Not started:** Unreal import, Palworld integration,
>   combat translation and stat/element/work translation. Their data shapes
>   are already defined and validated in `creature.json`. See [docs/roadmap.md](docs/roadmap.md).

## Quick start: the Studio (guided GUI)

1. Put this toolkit in a new, empty folder (for example `Desktop\AniimoStudio`).
2. Double-click **`Start-Studio.bat`** (Windows) or run **`./start-studio.sh`** (Linux/macOS).
3. First run: click **Install everything missing**. Python environment,
   AssetRipper and Blender are installed **inside that folder only**.
4. Select your Aniimo folder, scan, pick a creature, and click **Run all steps**.
   You get extracted assets, a rigged FBX for Unreal, and a **3D preview** of every
   variant with all animations (openable in Blender).

Details, folder layout and what is/isn't tested: [docs/studio.md](docs/studio.md).
The Palworld mods you will need for importing are listed in the Studio's
*Palworld mods* tab.

## Pipeline (what works today, command line)

```bash
pip install -e ".[unitypy]"

# 1. Inventory the game install (read-only; outputs must be outside it)
aniimo-pal scan "D:/Games/Aniimo" -o ws/manifests/aniimo.json --label "Aniimo 1.0"

# 2. List every object inside the readable Unity containers (encrypted files are never opened)
aniimo-pal inventory ws/manifests/aniimo.json "D:/Games/Aniimo" -o ws/objects.json

# 3. Build the creature catalog: species, Normal/Shiny/Prismana prefabs, mesh, materials,
#    textures, skeleton and animations, each with evidence and provenance
aniimo-pal catalog build ws/objects.json -o ws/catalog.json
aniimo-pal catalog list ws/catalog.json

# 4. Start a creature project (verified links auto-confirmed, inferred ones proposed)
aniimo-pal creature init ws --from-catalog ws/catalog.json --species foxlet
aniimo-pal creature review ws/creatures/aniimo_foxlet/creature.json
aniimo-pal creature associate ws/creatures/aniimo_foxlet/creature.json --confirm 12-14 --reject 15

# 5. Extract: UnityPy (PNG textures, OBJ preview meshes, bind poses, material/clip/skeleton JSON)
aniimo-pal creature extract ws/creatures/aniimo_foxlet/creature.json --root "D:/Games/Aniimo"
#    and/or AssetRipper (GLB models, or a Unity project with .anim clips)
aniimo-pal creature export-assetripper ws/creatures/aniimo_foxlet/creature.json \
    --root "D:/Games/Aniimo" --mode project --assetripper "C:/Tools/AssetRipper/AssetRipper.GUI.Free.exe"
#    (run it with --mode primary as well: the mesh GLB comes from the primary export)

# 6. Convert: rigged FBX for Unreal Engine 5.1 with all clips retargeted (needs Blender)
aniimo-pal creature convert ws/creatures/aniimo_foxlet/creature.json --blender "C:/Program Files/Blender Foundation/Blender 4.2/blender.exe"
```

| Command | Purpose |
|---------|---------|
| `scan`, `summary`, `validate`, `diff`, `verify`, `formats` | File inventory manifest; checks; game-update diffs |
| `inventory` | Unity object index (`objects.json`) via UnityPy |
| `catalog build / list / show` | Creature catalog with automatic asset association |
| `creature init / review / associate / validate / roll` | Resumable per-creature projects; exact wild/egg odds per regional form (`roll --biome`) |
| `creature extract` | UnityPy export of confirmed assets (source hashes re-checked) |
| `creature export-assetripper` | Headless AssetRipper export, mapped back to the creature's assets |
| `objects` | Search the object index, e.g. for stat, element or job data tables |
| `systems` | Show the (versioned, currently unverified) Aniimo/Palworld vocabularies used for validation |
| `creature convert` | Skin assembly + Blender job: rigged FBX with retargeted animation clips and a report |
| `creature preview` | Blender scene with every variant side by side and every animation on the timeline (+ still image) |
| `doctor`, `config` | Tool discovery; effective configuration |

Global options: `--config FILE` ([config/default.toml](config/default.toml)),
`--log-level`, `--log-file` (JSON lines). Catalog rules (variant keywords,
clip-role keywords, matching thresholds) are in
[config/catalog_rules.toml](config/catalog_rules.toml) and can be overridden
with `catalog build --rules`. Exit codes: `0` ok, `1` check failed, `2`
usage/config error.

## Install

Python ≥ 3.11. The scanner has no dependencies. Object inventory and extraction
need UnityPy (`pip install -e ".[unitypy]"`). AssetRipper is optional and runs
as a separate program
([download](https://github.com/AssetRipper/AssetRipper/releases)).

```bash
pip install -e ".[dev,unitypy,convert]"   # development: pytest, jsonschema, UnityPy, PyYAML, numpy
pip install bpy                           # optional: Blender as a Python module for conversion tests
```

## Legal and safety

Use only assets you have the right to use. The toolkit **never** decrypts,
de-obfuscates or bypasses protection: encryption-flagged files are reported
and never opened. Game files are only read, and outputs are refused inside the
game folder. No game files belong in this repository; `.gitignore` and
`tests/test_repo_hygiene.py` enforce this. See
[docs/legal-and-safety.md](docs/legal-and-safety.md).
